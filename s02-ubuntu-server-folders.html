    Ubuntu Server Folders

    Every file on the server lives in one tree that starts at /. Click a folder on the left (or use ← →) to see what's inside on a real-looking server, what it's for, and whether you should touch it.

    yours
    put your own files and apps here
    config
    settings: edit with sudo, carefully, and keep a backup
    data
    apps write here: read it and back it up, don't hand-edit
    system
    owned by apt: never add, edit or delete files
    virtual
    made up by the kernel on the fly, not on disk
    temp
    scratch space that gets wiped

      Disk full? Find what's big

      commandwhat it tells you
      df -hfree space per disk. Ignore the /dev/loop* lines (snaps).
      sudo du -xh --max-depth=1 / | sort -hsize of each top-level folder. -x stays on one disk, so it skips /proc.
      sudo du -sh /var/* | sort -husually the answer: logs, Docker or apt cache
      docker system dfspace used by images, containers, volumes, build cache
      journalctl --disk-usagesize of the systemd journal. Shrink: sudo journalctl --vacuum-size=200M
      sudo apt clean && sudo apt autoremovedrop downloaded .deb files and old kernels
      sudo apt install ncdu && sudo ncdu -x /interactive browser of what uses the space

      What to back up

      • /etc: all your configuration. Small, and painful to rebuild by memory. etckeeper puts it in git automatically.
      • /home and /srv (or wherever your apps live): code, .env files, uploads.
      • Databases: a dump (pg_dump, mysqldump), not a copy of /var/lib/postgresql while it's running.
      • Docker volumes in /var/lib/docker/volumes/: stop the container or use the app's own dump tool first.
      • /var/spool/cron/crontabs: everyone's crontabs.

      Not worth backing up: /usr, /boot, /var/cache, /tmp, /proc, /sys, /dev, /run. A reinstall brings those back.
