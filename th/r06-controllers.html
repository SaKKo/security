Controller และลำดับชั้นของ API

controller แปลง HTTP request หนึ่งครั้งเป็น JSON response หนึ่งครั้ง controller ของเราสั้น เพราะแต่ละชั้นของลำดับ class รับงานไปคนละอย่าง

action ของ controller ควร: โหลด record (จำกัดเฉพาะที่ผู้เรียกมีสิทธิ์เห็น) ส่ง params ที่กรองแล้วให้ model หรือ service และ render JSON ตามรูปแบบของ model ส่วน auth, การตรวจสิทธิ์ และการจัดรูป error ได้มาจากการสืบทอด ไม่ต้องเขียนในแต่ละ controller

แต่ละชั้นเพิ่มอะไรคลิกที่ class
เมื่อสร้าง controller ให้เปลี่ยน class แม่เป็น …::AppController ที่ถูกต้องทันที controller ปลายทางที่สืบทอด ApplicationController คือ bug ด้านความปลอดภัย: ไม่มี login ไม่มีการตรวจสิทธิ์

โครงสร้างของ resource controller

class Api::V1::Admin::RolesController < Api::V1::Admin::AppController
  before_action :set_client_application                 # parent from the URL
  before_action :set_role, only: %i[ show update ]      # the record, scoped to the parent

  # GET /api/v1/admin/client_applications/:client_application_id/roles
  def index
    result = @client_application.roles
    total_count = result.count
    key_mapping = {
      "created_at" => "created_at",
    }
    result = sort_with_mapping(result, key_mapping) if result.present?
    result, total_pages = paginate(result)
    render json: { roles: result.map(&:as_admin_json), total_pages:, total_count: }
  end

  def show
    render json: { role: @role.as_admin_json }
  end

  def create
    @role = Role.new(role_params)
    @role.save!                                         # raises → rescue_from → 400
    render json: { role: @role.as_admin_json }, status: :created
  end

  def update
    @role.update!(role_params)
    render json: { role: @role.as_admin_json }
  end

  private

  def set_client_application
    @client_application = ClientApplication.find(params[:client_application_id])
  end

  def set_role
    @role = @client_application.roles.find(params[:id])   # not Role.find!
  end

  def role_params
    p = params.require(:role).permit(:name, :description, :status, permissions: [])
    p[:client_application_id] = @client_application.id if action_name == "create"
    p
  end
end
รูปแบบเหตุผล
set_* before_actionsโหลด record ครั้งเดียวก่อน action find raise → 404 อัตโนมัติ
@client_application.roles.findดึงผ่าน parent: id ของ role จากแอปอื่นจะได้ 404 ไม่รั่วไหล (IDOR)
save! / update!ไม่มี if/else ถ้าล้มเหลวจะ raise แล้วกลายเป็น JSON 400 มาตรฐาน
require(:role).permit(…)whitelist field ที่อื่นใน body ถูกตัดทิ้ง (mass assignment)
p[:client_application_id] = …parent มาจาก URL ที่ผู้ใช้ได้รับอนุญาตแล้ว ไม่ใช่จาก body
as_admin_jsonmodel เป็นผู้กำหนดรูปแบบ JSON ส่วน controller เลือกว่าจะใช้แบบไหน
{ roles:, total_pages:, total_count: }ทุกรายการมีรูปแบบเดียวกัน front end จึงใช้ component ตารางตัวเดียวได้

ดูการตอบสนองจริง

สรุปเรื่อง params

params[:id]                                   # from the path: /users/:id
params[:page]                                 # from the query string: ?page=2
params.require(:role)                         # JSON body {"role": {...}}; raises if missing
      .permit(:name, :status, permissions: [])# arrays need [] ; nested hashes need { }
params.permit(:sort_field, :sort_order)       # optional query params, no require
params[:info].to_bool                         # query values are strings
action_name                                   # "create", "update", ...

status code ที่เราใช้

statusเมื่อมาจาก
200 :okอ่าน / แก้ไขสำเร็จrender json:
201 :createdสร้างสำเร็จrender json:, status: :created
400 :bad_requestข้อมูลไม่ถูกต้อง ขาด param หรือเปลี่ยนสถานะไม่ได้AppError, RecordInvalid, ParameterMissing, AASM::InvalidTransition
401 :unauthorizedไม่ได้ login / token ไม่ถูกต้องAppAuthenticationError, JWT errors
403 :forbiddenlogin แล้วแต่ไม่มีสิทธิ์AppPermissionDenied
404 :not_foundไม่มี record นี้ (หรือไม่ใช่ของคุณ)ActiveRecord::RecordNotFound

ผู้ใช้เรียก GET /client_applications/A/roles/R โดยที่ role R เป็นของแอป B จะเกิดอะไรขึ้นกับ set_role ของเรา?

@client_application.roles.find(id) เพิ่ม WHERE client_application_id = A ถ้าใช้ Role.find(id) จะได้ 200 ซึ่งคือ bug แบบ IDOR

client_application_id ของ role ใหม่ควรมาจากไหน?

ผู้ใช้ได้รับอนุญาตสำหรับ parent ใน URL แล้ว ถ้า permit id จาก body เขาจะสร้าง role ในแอปไหนก็ได้
