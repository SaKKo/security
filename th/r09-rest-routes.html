Route แบบ RESTful และ Resourceful

REST หมายถึง: URL ใช้ตั้งชื่อสิ่งของ (resource) ส่วน HTTP verb บอกว่าจะทำอะไรกับมัน resources ของ Rails เปลี่ยนแนวคิดนี้เป็น route, action ของ controller และ helper method ได้ในบรรทัดเดียว

ห้า action ครอบคลุมเกือบทุกอย่าง

verbpathactionความหมายสำเร็จ
GET/client_applications#indexรายการ200
POST/client_applications#createสร้างใหม่201
GET/client_applications/:id#showอ่านหนึ่งรายการ200
PATCH / PUT/client_applications/:id#updateแก้ไขหนึ่งรายการ200
DELETE/client_applications/:id#destroyลบหนึ่งรายการ (สำหรับเรา: soft delete)200
แอป API-only ไม่มี new และ edit เพราะ action เหล่านั้นมีไว้ render ฟอร์ม HTML เท่านั้น

path ที่ดี และ path ที่ไม่ดี

✗

POST /api/getRoles?appId=42
POST /api/v1/admin/createRole
GET  /api/v1/admin/deleteUser?id=7
POST /api/v1/admin/role/update
GET  /api/v1/admin/RolesForApp/42

✓

GET    /api/v1/admin/client_applications/:id/roles
POST   /api/v1/admin/client_applications/:id/roles
DELETE /api/v1/admin/users/:id
PATCH  /api/v1/admin/client_applications/:ca_id/roles/:id
POST   /api/v1/admin/users/:id/toggle_admin
  • ใช้คำนามพหูพจน์ snake_case และมีเวอร์ชันใต้ /api/v1
  • verb คือ HTTP method ห้ามเปลี่ยนข้อมูลด้วย GET เพราะเบราว์เซอร์ proxy และ crawler เรียก GET ซ้ำได้ตามสะดวก
  • ความเป็นเจ้าของอยู่ใน path: role ของแอปพลิเคชันจะซ้อนอยู่ใต้แอปนั้น
  • อนุญาตให้มี verb ใน path เฉพาะเมื่อเป็น member action สำหรับการเปลี่ยนสถานะที่ไม่ใช่ CRUD ธรรมดา (toggle_admin, activate)

Resourceful routing

resources :client_applications, only: %i[ index show create update ]   # always list actions

resources :client_applications do
  resources :roles, only: %i[ index show create update ]                # nested: /client_applications/:client_application_id/roles
end

resources :users, only: %i[ index show ] do
  member do
    post :toggle_admin                       # /users/:id/toggle_admin      → acts on one
  end
  collection do
    get :export                              # /users/export                → acts on the set
  end
end

resource :profile, only: %i[ show update ]   # singular: no :id, it's "mine" → profiles#show

namespace :api do                            # path /api/..., module Api::, folder api/, helper api_...
  namespace :v1 do
    namespace :admin do
      resources :users
    end
  end
end
ระบุ only: เสมอ route ที่ไม่ได้ใช้คือ route ที่คนอื่นลองยิงได้ และยังกลายเป็นสิทธิ์ใน Permission.all_admin_permissions ด้วย ซ้อนกันไม่เกินหนึ่งชั้น

การเปลี่ยนสถานะเป็น member route

แต่ละ event ของ AASM ใน model จะกลายเป็น member route แบบ POST และ action ใน controller ที่เรียก event แบบ bang ส่วน UI ของ admin อ่าน actionables จาก JSON เพื่อรู้ว่าต้องแสดงปุ่มไหน:

# POST /api/v1/admin/users/:user_id/user_roles/:id/activate
def activate
  @user_role.activate!                                   # AASM::InvalidTransition → 400
  render json: { user_role: @user_role.as_admin_json }   # includes actionables: ["inactivate"]
end

วิธีนี้ดีกว่า PATCH status=active เพราะกฎการเปลี่ยนสถานะยังอยู่ใน model แต่ละ event มีสิทธิ์ของตัวเอง และ audit log บอกได้ว่าเกิดอะไรขึ้น

route ที่ไม่ใช่ resource

namespace :admin do
  post   "sessions",    to: "sessions#create"    # login       → api_v1_admin_sessions
  get    "sessions/me", to: "sessions#me"        # who am I    → api_v1_admin_sessions_me
  delete "sessions",    to: "sessions#destroy"   # logout
end

บาง endpoint เป็นการกระทำมากกว่าสิ่งของ (login, ตรวจ token) ให้เขียนด้วย verb "path", to: "controller#action" แล้ว Rails จะตั้งชื่อ helper จาก path ให้

สร้าง route แล้วดูผลลัพธ์

ตัวสร้าง routeเปิดปิด option แล้วคลิกที่แถว

ทุก Prefix กลายเป็นสอง method: …_path (เฉพาะ path) และ …_url (มี host ด้วย) ลองใน console ผ่าน app:

route ทั้งหมดของเรา

Rails.application.routes.draw do
  get "health", to: "application#health"

  namespace :api do
    namespace :v1 do
      namespace :admin do
        post   "sessions",    to: "sessions#create"
        get    "sessions/me", to: "sessions#me"
        delete "sessions",    to: "sessions#destroy"

        resources :users, only: %i[ index show ] do
          member do
            post :toggle_admin
          end
          resources :user_roles, only: %i[ index create ] do
            member do
              post :activate
              post :inactivate
            end
          end
        end

        resources :client_applications, only: %i[ index show create update ] do
          resources :roles, only: %i[ index show create update ]
          resources :permissions, only: %i[ index ]
        end
      end

      namespace :client do
        post "auth/login",  to: "auth#login"
        get  "auth/verify", to: "auth#verify"
        resources :roles, only: %i[ index ]
        resources :permissions, only: %i[ index ]
      end

      namespace :public do
        post "two_factors/enroll",  to: "two_factors#enroll"
        post "two_factors/confirm", to: "two_factors#confirm"
        post "two_factors/disable", to: "two_factors#disable"
      end
    end
  end
end

การเปลี่ยนสถานะที่ไม่ใช่ CRUD: event ของ AASM ที่เปิดเป็น member route แบบ POST

helper ของ GET /api/v1/admin/users/:user_id/user_roles คืออะไร?

namespace + parent (เอกพจน์) + child (พหูพจน์): api_v1_admin + user + user_roles
